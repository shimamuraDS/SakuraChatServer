# 新发送消息的自动删除

## 启用与范围

默认关闭。客户端侧边栏齿轮 → 自动删除设置，可选择关闭、24 小时、7 天或 30 天，勾选范围说明后确认保存。此设置仅针对当前账号以后发出的私聊消息，不改变接收消息的发送者设置，不是全会话双方共同设置。

服务端设置确认后的新发送请求在首次入库时记录期限。与设置并发、已在处理中的请求可能沿用之前的设置；只有新消息取得期限，旧消息不追溯补设。关闭或修改设置不取消已有期限。期限从服务器入库时计算，不从阅读时计算；不是秘密聊天阅后即焚。

双方的新客户端可看到消息的自动删除时间。到期由服务器为双方删除，继承手动删除的事件、权限及幂等规则。离线客户端只有联网同步后才能获知删除；不能清除截图、导出、旧备份或磁盘残留。

## 部署前置

先备份并手动执行 database/005_message_retention.sql，前提是已完成 002、003、004。该脚本仅建立 user_message_retention 和 message_expiry，不为旧消息排期，不删除历史数据。本轮未执行 SQL 或启动程序。

新消息查询、入库及隐私查询依赖新表；缺表时会失败，不回退成忽略用户期限的保存方式。两个聊天实例使用同一数据库和迁移版本。

## 实现

- 设置通过现有 1040/1041 接口的 set_retention 动作提交 seconds，服务端只接受 0、86400、604800、2592000，并只修改已认证账号。
- 消息入库事务里按发送者设置写入 message_expiry，和原消息一同提交；重试原 UUID 不重置期限。
- ChatServer 拥有可停止、可 join 的后台线程，通常每 5 秒扫描至多 20 条到期任务，失败退避至 30 秒。线程持有数据库管理器的共享所有权，不使用 detached 线程，不在网络或业务队列线程执行扫描。
- 两个节点可重复扫描相同任务，DeleteMessage 的行锁及唯一事件约束保证重复处理幂等。成功删除会在同一事务里清除期限任务，不反复累计事件。
- 服务端读取已到期的消息时即隐藏正文并返回删除状态；即使后台扫描暂时落后，也不通过新的历史/状态读取返回原文。数据库中的当前正文由删除任务清空，备份/binlog 不受此操作清理。
- 客户端按既有约 10 秒事件轮询持久删除标记，显示期限是提示，不承诺离线端在精确时刻擦除。

## 尚未验证与限制

仅进行编译检查，未执行期限到达、进程重启、双节点竞争、时钟偏差、SQL 故障或大量积压测试。5 秒是正常轮询间隔，不是删除时效 SLA；吞吐受批量大小、数据库响应和节点运行情况影响。驱动层 SQL 阻塞也可能延迟关闭线程。

未实现管理员积压看板、失败任务隔离、会话级双方协商、按已读起算、旧消息批量追溯、离线端可靠物理擦除、数据库备份自动清理。发送者设置权限不等于其他参与者可任意修改已有消息的期限。
